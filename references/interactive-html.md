# 解释型交互HTML

先读主入口。使用与通俗改写相同的原文、必要上下文和完整性要求，不能因转成图形而减项。实现方式按材料选择，不强制框架、Canvas、双栏、图数或模板。

## 内容与阅读方式

- 先确定读者要回答的问题。流程顺序可用时间线，真实依赖可用关系图，差异可用对照，可调条件确实影响结果时才做互动示例。箭头写实际关系；演示不是实测结果。
- 默认是连续可阅读、可定位、可查找的说明文档。不要全屏逐页、固定页高、自动播放、一屏一句或巨大标题搭配数字卡片。用户另要幻灯片属于不同任务。
- 结论、关键前提、例外、未完成范围与历史属性默认可读，不必悬停、播放或点开全部卡片。补充详情可展开，但其中的解释要完整并可定位。原文查看器只是证据入口，不能补救解释中的遗漏。
- 每个图表或控件都有阅读用途。筛选只改变显示范围，不改变全局结论；显示当前筛选及清除入口。有搜索时，区分无结果与没有数据。
- 数字标对象、单位、口径与必要分母；不相加包含或不同集合，不把未知画成0。没有完成率依据就不用进度图。历史提案、已接受框架与当前产品状态不能画成同一条全绿成功链。
- 标题、分组和图形关系也属于事实表达。原文只给某一对象的状态，不能把该状态扩大到同列全部对象；原文未定义的内部说法保留归属并说明未知，不把它另造为页面概念。
- 有时间线时区分事件时间、运行时长、预算和未知。没有结束记录不能拿下一条消息时间冒充耗时。
- 来源链接指向它支持的内容。需要保留引用关系的材料，用相对文件、内嵌来源或清楚的文档映射；不能发明证据或未实现入口。

## 实现与验证

优先用语义HTML、正常文本、表格和有标签的原生控件。图形有文字或数据等价信息，不只靠颜色；控件有可访问名称，键盘能操作，焦点可见且不被无故困住。关键说明不只放tooltip。

按页面内容验证搜索、筛选、展开、复位与来源定位；同时检查默认和操作后的状态，没有把失败或限制藏掉。允许真正二维的表或图局部横滚，正文应重排、可放大阅读；命令完整可复制。

操作名称与实际作用一致：“展开解释”只展开解释，“查看原文”只查看来源。没有解释详情就不增加解释展开按钮；搜索和筛选保留全局限制，并能恢复全文，不为凑交互增加无用途控件。

离线交付时，内嵌必需资源或按相对路径附带，不依赖CDN、作者电脑或外部字体。实际断网并换目录打开检查；未验证的打开方式或环境如实说明。不要把源码静态存在当浏览器已运行。

逐项检查原信息在解释正文、图例、表格或解释性详情中的位置。再核对图形的连线、面积、分组、顺序和筛选是否改变原意。任一遗漏不能靠“原文已附”或交互好看抵消。

网页检查仅证明所测行为，不证明真人理解，也不等于完整WCAG合规。W3C的COGA是补充指导；阅读相关AAA条款和中文排版草案不能统称AA强制要求，不设中文每行40字或固定句长的通用门槛。
