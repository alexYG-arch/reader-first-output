## 发现的问题与两次修复

8 个构造主案例共 10 条回复，独立 AI 审阅首次为 7 例通过、1 例失败；另 3 项检查通过。26 条必需信息均出现，仍因一处无依据新增判整例失败。

失败场景：材料说“网络中断时，请求可能停在已提交”；下一问只说明当前看到“已提交”。回答却建议“等网络恢复”，将一个条件场景当成了当前事实。

第一次补充“不把假设或条件当成事实、也不由当前状态倒推原因”，同题三轮复测仍出现“等网络恢复”，保留失败。第二次进一步明确“建议也不暗中预设原因；未确认情况保留为条件或不补原因”，同题三轮复测通过。三轮自然输入和原断言都没有改，生成端没有接收参考答案。

最新第二轮中的建议为：

> 建议先别关。“已提交”还不能确认文件已写入完成；等显示“已保存”再关闭更稳妥。如果一直停在“已提交”，先保留当前页面，并把内容另存一份。

它不再断定当前断网。“另存一份”是普通人工保留内容的建议，未宣称产品存在自动备份功能。

7 个未受影响案例和 3 项额外检查继承首轮通过结果；只有受影响多轮案例在第三版本机默认规则下重新生成三条回复并通过。不能称为全部案例都在第三版重跑。每一轮失败、原始回答和审阅均保留在本地记录中。

## v0.4.2 的变更与发布验证

这条通用语义修复现写入 Skill 本体、项目短稿和新增全局短稿，使其他安装者也能得到修复；新增安装说明，区分自动选用与用户级默认指令。Skill ZIP 从 6 个变为 7 个文本文件。没有加入业务执行器或修改用户的项目代码。

本次 v0.4.2 在新 CLI 聊天中用相同自然输入重新生成该例 3 条回复，4 条原断言通过独立 AI 审阅；首轮实际读取的新 Skill 正文逐字匹配，后两轮没有重复读取。三次调用分别耗时 28.319、16.057、20.116 秒，包含进程启动和回答时间，不是纯生成速度基准。官方 Skill 结构检查、解压换目录与 7 个文件一致性检查通过。

本次发布检查与新增运行结果记录在 [机器可读摘要](global-validation-summary.json)，与上面的历史结果分开。旧 v0.4.1 的完整语料与浏览器测试没有因文档更新自动变成 v0.4.2 重新验收。

## 证据限制

- 自动加载和内容正确分别检查；读取成功不保证以后每条模型回答都正确。
- AI 语义检查不等于真人理解测试；没有无 Skill 对照，不给出可读性提升比例。
- HTML 在这轮仅用于验证多轮任务从 HTML 切回 Chat 的能力，没有重做浏览器或视觉验收。
- 未验证所有宿主、模型、Windows、所有已打开的 Desktop 聊天，或完全离线启动。
- 安装步骤可按 [安装说明](INSTALL-CODEX.md) 在自己的环境验证，不需要公开私人会话日志。
