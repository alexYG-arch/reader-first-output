## 为什么先前自动化没有完成

Chrome DevTools 的 [已确认问题 #3033](https://github.com/ChromeDevTools/chrome-devtools-mcp/issues/3033) 解释了 macOS 原生 select 的这类限制：系统弹出菜单出现后，发往页面渲染器的 CDP 按键不一定能驱动系统菜单。该资料与本机现象吻合，是归因支持，不替代本机实测。

因此，仅把页面内 `ArrowDown/Enter` 或 `selectOption()` 执行成功当作完整键盘验收都不可靠：前者可能卡在输入工具边界，后者检查的是选择与 change 处理，不能证明原生菜单的键盘导航。

## 修正后的验收方法

1. 保存原 HTML 和哈希，记录实际运行浏览器版本；不能拿磁盘版本代替已启动进程的版本。
2. 只用 Tab 聚焦；用空格展开菜单，在原生辅助功能树或系统截图中确认菜单确实出现。
3. 使用系统级方向键和回车提交；核对选中值、结果显示和实际 input/change。
4. 验证 Esc 取消、反向选择与恢复全部。
5. 同时测试没有自定义按键处理的最小原生控件。保留自动化失败，不为迎合测试改写原生控件。
6. 如果工具无法安全控制目标浏览器实例，记录未运行和版本差异；不要重启用户浏览器、改系统策略或把未验证改成通过。
